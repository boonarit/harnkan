# ADR 006 · Gemini เป็นตัวอ่านสลิปค่าเริ่มต้น (Claude ยังเลือกได้)

**สถานะ:** ใช้อยู่ · 2026-09 · แทนค่าเริ่มต้นเดิมใน ADR 004 (Claude)

## บริบท
- งานอ่านสลิปคือ "ดูรูป 1 ใบ → คืน JSON 9 field" ไม่ต้องใช้การคิดหลายขั้น รุ่นเล็กที่อ่านรูปได้และบังคับ JSON ได้ก็พอ
- ค่าใช้จ่ายต่อรูปคูณจำนวนสลิปทุกวันคือค่าใช้จ่ายหลักของระบบ ผู้ดูแลต้องการตัวเลือกที่ถูกลงและใช้บัญชี Google ที่มีอยู่
- ต้องไม่เพิ่ม dependency (กติกาของรีโป) และต้องสลับกลับได้ถ้าคุณภาพไม่พอ

## ตัดสินใจ
- เพิ่ม `GeminiSlipReader` (implement `SlipReader` เดิม) เรียก REST `generateContent` ด้วย `fetch` ตรง **ไม่มี SDK ใหม่**
- บังคับผลด้วย `responseMimeType: application/json` + `responseSchema` ที่**แปลงจาก `SLIP_TOOL` ตัวเดียวกับ Claude** → field ชุดเดียวกันเสมอ · ผลผ่าน `normalize()` ตัวเดียวกัน
- key ส่งทาง header `x-goog-api-key` เท่านั้น (ไม่ใส่ `?key=` ใน URL เพื่อไม่ให้ไปอยู่ใน log ของ proxy/tunnel) · ข้อความ error ถูกลบ key ออกก่อนเข้า log
- `AI_PROVIDER=gemini|claude` (ค่าเริ่ม gemini) · `ClaudeSlipReader` เก็บไว้ครบ
- `SLIP_MODEL` ของ Gemini **ไม่มีค่าเริ่มต้นในโค้ด** — ชื่อรุ่นเปลี่ยนบ่อย ผู้ดูแลเลือกจากรายชื่อรุ่นใน AI Studio แล้วใส่ใน env · config ไม่ยอมเริ่มถ้า `FAKE_AI=0` แต่ขาด key หรือรุ่นของ provider ที่เลือก
- ใช้ **paid tier เท่านั้น** กับสลิปจริง (free tier อาจถูกนำข้อมูลไปปรับปรุงผลิตภัณฑ์) + budget alert ใน Google Cloud + `AI_DAILY_CAP` ในแอป

## ผลที่ตามมา
- สลับผู้ให้บริการได้ด้วย env ตัวเดียว ไม่ต้องแก้โค้ด · ข้อผิดพลาดทุกแบบ (429, 500, JSON เพี้ยน, ถูกบล็อก) จบที่ "ขอให้พิมพ์ยอด" เหมือนกัน
- ยังไม่มีการวัดความแม่นและค่าใช้จ่ายจริงเทียบกันระหว่าง Gemini กับ Claude บนสลิปไทย — ต้องวัดช่วงทดสอบจริง (ระยะ 5) ถ้าอ่านผิดบ่อยให้สลับกลับด้วย `AI_PROVIDER=claude`
- ไม่มี retry อัตโนมัติเมื่อโดน 429 (ผู้ใช้พิมพ์ยอดแทน) — เพิ่มได้ถ้าเจอบ่อย
- ข้อมูลรูปสลิปไปอยู่ที่ Google แทน Anthropic → อัปเดต `docs/PRIVACY.md` แล้ว
